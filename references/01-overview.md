# 01 運作方式

## 架構

```
TradingView 警報 ──HTTPS──▶ Caddy（443）──▶ tv_webhook.py（127.0.0.1:8780）──▶ OneBullEx Open API V2
```

- **Caddy**：自動申請、更新 HTTPS 憑證，只把 `/webhook` 轉給接收程式。
- **tv_webhook.py**：檢查來源 IP 與 passphrase，解讀訊息，查持倉、下市價單、確認成交、核對持倉。
- 接收程式只監聽本機，不直接對外開放。
- API key 存在主機的 `/etc/onebullex-tv.env`，只有 root 和服務帳號讀得到，不會出現在 TradingView 訊息裡。

## 目標持倉

每則訊息描述的是「這個交易對**現在應該**持有多少張」，不是「再買幾張」：

| 實際持倉 | 訊息目標 | 程式動作 |
| --- | --- | --- |
| 0 | 多 3 張 | 開多 3 張 |
| 多 3 張 | 多 3 張（重送） | 不下單 |
| 多 3 張 | 多 5 張 | 加多 2 張 |
| 多 3 張 | 空 2 張 | 先平多 3 張、確認成交，再開空 2 張 |
| 多 3 張 | 0 | 平多 3 張 |

好處：TradingView 偶爾重送或漏送一則警報，下一則到達時持倉會自動對齊，不會越下越多。

TradingView 策略警報的 `{{strategy.market_position}}`、`{{strategy.market_position_size}}` 本身就是目標持倉，所以策略不用改，只要設定警報訊息。

## 下單規則

- 一律市價單；先平倉並確認成交，再開倉並確認成交，最後核對淨部位等於目標。
- 帳戶同時有多單和空單時，平到只剩目標方向；分倉帳戶有多筆持倉時，從最早開的一筆開始平。
- 下單失敗或沒有完整成交：停止這則訊號、記錄錯誤，**不自動重送**。下一則訊號會依實際持倉重新計算。
- 處理中又收到同一交易對的新訊號：只執行最新的一則。

## 限制

- **只能表達淨部位**：TradingView 策略同一時間只有一個方向的持倉，所以實盤也是淨部位。策略裡只用變數計算、顯示在面板上，但沒有用 `strategy.entry`／`strategy.order` 真的下單的部位，不會出現在實盤。
- **出場靠 TradingView 送訊號**：主機、網路或 TradingView 中斷期間不會自動平倉。需要保護時，在 OneBullEx 另外設定。
- **價格來源不同**：訊號用 TradingView 圖表的價格（例如幣安 BTCUSDT.P）計算，成交用 OneBullEx 的市價，成交價和回測會有差距，另有滑價、手續費、資金費。
- **重繪（repaint）**：會重繪的策略，實盤訊號可能和回測不一致。先用試跑模式觀察。
- **同一個交易對只用一個訊號來源**：同一個帳戶的同一個交易對，不要同時用 TradingView 和其他程式（或手動）下單，目標持倉會互相抵消。
