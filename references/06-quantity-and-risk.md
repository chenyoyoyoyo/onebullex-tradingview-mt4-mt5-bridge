# 06 張數、名目價值、槓桿與防呆

## 單位

OneBullEx 下單單位是**整數張**。以 BTCSPARTANS_USDT（1 張 = 0.0001 BTC）、BTC 價格 80,000 為例：

| 張數 | BTC 數量 | 名目價值 |
| --- | --- | --- |
| 1 | 0.0001 | 約 8 USDT |
| 10 | 0.001 | 約 80 USDT |
| 100 | 0.01 | 約 800 USDT |

這只是單位示例，不是下單建議。面值以 `obx_tool.py spec <交易對>` 查詢為準。

## 調整每單大小

在 TradingView 警報訊息裡改：

- 範本 A（幣數）：改策略本身的下單數量，或加 `"multiplier"`。
- 範本 B（份數）：改 `"multiplier"` 的數字，例如 10 → 20，每份就從 10 張變 20 張。
- 範本 C：改 `qty`。

**在空倉時改**。持倉中途改倍數，下一則訊號會用新倍數重算目標，一次把整個部位補到（或減到）新張數，均價會和策略差很多。

## 槓桿

槓桿**不改變名目價值與價格損益**，只改變佔用多少保證金。

- 預設 `TV_LEVERAGE=0`：沿用 OneBullEx 帳戶上該交易對的槓桿設定。
- 固定槓桿：`sudo bash install.sh set TV_LEVERAGE 10`，之後每次開倉前會設定成 10 倍。
- 設定值超過該交易對的最高槓桿時，開倉會失敗並記錄錯誤；最高槓桿用 `obx_tool.py spec` 查。
- **在空倉時改**：已有持倉時改槓桿，交易所可能回 `order_leverage_not_match_position_leverage`。

## 保證金模式：先確認是全倉還是逐倉

| 模式 | 爆倉由什麼決定 |
| --- | --- |
| 全倉 | 整個合約帳戶的權益能不能撐住所有持倉的虧損。槓桿高只是保證金佔用少，爆倉點主要看**總名目價值相對於帳戶餘額**。 |
| 逐倉（或分倉下每筆獨立計算） | 每一筆持倉只用自己的保證金。100 倍代表反向約 1% 就可能被強平。 |

高槓桿搭配逐倉，對會分批加碼、沒有停損的策略（例如攤平）特別危險：還沒到下一次加碼點就可能被強平。

## 用「能承受多大跌幅」決定張數

沒有停損的策略，張數應該從「帳戶能承受價格反向多少」倒推，而不是從槓桿上限推。

令每張面值 C、帳戶權益 E、最大持倉 N 張、持倉均價 A：

```
價格反向到 A − E ÷ (N × C) 附近，帳戶權益會被虧光（多單；未計手續費與維持保證金，實際會更早爆倉）
```

例：E = 100 USDT、N = 50 張、C = 0.0001 BTC → E ÷ (N × C) = 20,000 點。均價 80,000 的多單，跌到約 60,000 會虧光。

會分批加碼的策略，要用**加滿後的總張數與均價**計算，並確認在下一次加碼之前不會先爆倉。

## 防呆設定（選用）

| 指令 | 作用 |
| --- | --- |
| `sudo bash install.sh set TV_MAX_QTY 100` | 目標持倉超過 100 張就不執行（防止 multiplier 多打一個 0） |
| `sudo bash install.sh set TV_SYMBOLS BTCSPARTANS_USDT` | 只接受這些交易對，逗號分隔；`all` = 不限 |
| `sudo bash install.sh set TV_LEVERAGE 10` | 開倉前固定槓桿；`0` = 沿用帳戶設定 |

預設全部不限制，下單數量由使用者的策略與警報訊息決定。

## 資金

- 合約權益與可用保證金：`sudo bash install.sh balance`。
- 斯巴達的贖回從資金帳戶支付，不要把資金全部轉進合約帳戶。
