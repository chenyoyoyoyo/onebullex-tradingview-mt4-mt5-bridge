# 08 MT4／MT5 同步到斯巴達

給在 MT4 或 MT5 上交易（手動或用 EA）的策略方：在 MT4／MT5 掛一個同步程式 `OneBullExSync`，你在 MT 上的持倉會自動同步到 OneBullEx 斯巴達機器人帳戶。原本的交易方式不用改。

```
MT4／MT5（你的策略 EA 或手動下單）
   │ OneBullExSync 每秒讀取持倉（MT5 另外在每次成交時立刻讀取）
   │ 持倉有變化就送出；沒變化每 60 秒重送一次
   ▼
接收程式（跟 TradingView 共用同一套，見 03）
   │ 查實際持倉 → 補差額 → 確認成交
   ▼
OneBullEx 斯巴達機器人帳戶
```

- **EA** 是掛在 MT 圖表上自動執行的小程式。`OneBullExSync` **不會在 MT 上下單**，只讀取持倉。
- 送出的是**目標持倉**，所以重送不會重複下單；漏掉一次，下一次也會自動對齊。
- 只同步**已成交的持倉**。掛單成交後才同步；停損、停利在 MT 觸發平倉後，OneBullEx 也會跟著平倉。部分平倉也會同步。
- **MT 是模擬帳戶，不代表 OneBullEx 也是模擬。** 接收程式在正式模式（LIVE）時，MT 模擬帳戶的單也會讓 OneBullEx 真實下單。

## 能同步的商品

OneBullEx 必須有對應的合約。目前主要是：

| MT 商品（各券商名稱可能不同） | OneBullEx |
| --- | --- |
| XAUUSD、GOLD、XAUUSD.m… | `XAUSPARTANS_USDT` |
| BTCUSD | `BTCSPARTANS_USDT` |
| ETHUSD | `ETHSPARTANS_USDT` |

外匯貨幣對、指數、原油等，OneBullEx 沒有對應合約，不能同步。

## 需要準備

| 項目 | 說明 |
| --- | --- |
| MT4／MT5 帳戶 | 正式使用是策略方自己的券商帳戶。只是測試的話：MT5 可用內建的 **MetaQuotes-Demo** 模擬帳戶（「檔案 → 開立帳戶」→ 選 MetaQuotes Ltd. → 開設類比帳戶），不用找券商；MT4 要到券商（例如 XM、OANDA）開模擬帳戶，見下方「登入並確認連線」 |
| Passphrase | 接收程式安裝時顯示的那串。同一套接收程式、沒有更換過的話，MT4、MT5、TradingView 都用同一串。它不是券商密碼，也不是 OneBullEx API Secret，見下方「Passphrase」 |
| 跑 MT 的電腦 | 你自己的電腦就可以（Windows 或 Mac；Mac 已實測）。同步程式跑在 MT 上，MT 關掉、電腦睡眠或斷網就不會同步。想 24 小時穩定運行，可以選擇租 **Windows VPS**（固定 IP），見 [09](09-windows-vps.md)。接收程式不能裝在這台電腦上，仍需要 Linux 的接收程式主機 |
| 接收程式主機 | 照 [02](02-server-setup.md)、[03](03-install.md) 安裝，取得 Webhook URL 與 passphrase。**一套接收程式對應一個機器人帳戶**；同一台主機上已有正式策略在跑時，測試請另開主機、用另一個機器人帳戶 |
| 同步程式 | 本倉庫的 `mt/OneBullExSync.mq4`（MT4）或 `mt/OneBullExSync.mq5`（MT5） |

> **用手機下單的策略方**：MT4／MT5 手機 App 不能執行任何 EA。可以照常用手機下單，但要另外有一台 Windows VPS（或一直開著的電腦）的 MT **登入同一個帳戶**並掛上同步程式；同步程式讀的是帳戶持倉，手機下的單也會被同步。手機下的單是手動單，`MagicFilter` 要用 `-1` 或 `0`。

| 開圖表 | 市場報價右鍵 → 圖表視窗 | 市場報價右鍵 → 開啟圖表 |

## 登入並確認連線（先做，再查規格）

1. MT4 第一次啟動可能跳出「交易伺服器」精靈，預設的 MetaQuotes-Demo 不一定是你的券商。搜尋券商名稱，選**帳戶實際指定的伺服器**（開戶信或會員頁會寫，例如 `券商名-Demo 數字`），再選「既有交易帳戶」輸入帳號密碼。
2. 券商**會員網站的密碼**和 **MT 交易密碼**可能不同，登入 MT 要用交易密碼。
3. **標題列顯示帳號不代表登入成功。** 確認：
   - 右下角的連線狀態不是「帳戶無效／無連線」，而是顯示傳輸速度；
   - 「新交易單」按鈕可以按（不是灰色）；
   - 市場報價持續跳動，圖表是今天的 K 線。
4. 不確定時看 MT 下方「日誌」分頁的登入結果。不要只憑一個舊報價判定已連線。


## 先分清楚三種 IP

| IP | 用途 | 設定在哪裡 |
| --- | --- | --- |
| MT 所在電腦的對外 IP（Windows VPS 或家用網路） | MT → 接收程式。接收程式只接受白名單內的來源 | 接收程式主機的 `TV_ALLOWED_IPS`（步驟 1） |
| 接收程式主機的固定 IP | 接收程式 → OneBullEx | 只有 API key 有綁 IP 時才需要（出現 `not-at-white-list`） |
| HTTPS 網址裡的 IP（例如 `203-0-113-10.sslip.io`） | 就是接收程式主機的 IP，組成免費網域 | 不用另外設定 |

## 1. 允許 MT 所在電腦的 IP

在**跑 MT 的那台電腦**打開 https://checkip.amazonaws.com 查詢對外 IP，然後在**接收程式主機**執行：

```bash
sudo bash ~/onebullex-tradingview-mt4-mt5-bridge/bridge/install.sh set TV_ALLOWED_IPS tradingview,<MT電腦的IP>
```

- `tradingview` 代表保留 TradingView 官方 IP；不用 TradingView 可以只填 MT 電腦的 IP。多台用逗號分隔。
- 家用網路的 IP 可能會變。之後出現 `HTTP 403` 時，執行 `sudo bash install.sh recent`，找 `拒絕：來源 IP ... 不在允許清單` 那一行，把新的 IP 加進來。不要為了省事改成 `all`。
- 券商提供的 VPS 或 MQL5 虛擬主機，對外 IP 通常不固定，不適合 IP 白名單；建議自己租固定 IP 的 Windows VPS。

## 2. 放入同步程式並編譯

1. 下載同步程式：**MT4 用 `OneBullExSync.mq4`，MT5 用 `OneBullExSync.mq5`**，不能混用。從 GitHub 檔案頁按「Download raw file」，確認存下來的副檔名是 `.mq4`／`.mq5`，不是 `.txt` 或 `.html`。
2. 放進 MT 的資料資料夾：
   - **Windows**：MT「檔案（文件）→ 開啟資料資料夾」→ 進入 `MQL4\Experts`（MT5 是 `MQL5\Experts`）→ 把檔案放進去。
   - **Mac**：Mac 版 MT 是 Windows 程式包了一層 Wine，「開啟資料資料夾」打開的是 Wine 的檔案視窗，**不能從 Finder 拖檔或貼上**。在那個視窗上方的**路徑欄點兩下**，可以看到完整的 Windows 路徑，例如 `C:\Program Files (x86)\MetaTrader 4\MQL4\Experts`。把 `C:` 換成 Wine 資料夾，就是 Mac 上的位置。用 Finder 選單「前往 → 前往資料夾」（Command+Shift+G）打開後，把檔案複製進去。實測時的路徑：

     ```text
     MT4：~/Library/Application Support/net.metaquotes.wine.metatrader4/drive_c/Program Files (x86)/MetaTrader 4/MQL4/Experts/
     MT5：~/Library/Application Support/net.metaquotes.wine.metatrader5/drive_c/Program Files/MetaTrader 5/MQL5/Experts/
     ```

     注意 MT4 是 `Program Files (x86)`、MT5 是 `Program Files`。不同電腦或安裝方式可能不同，以路徑欄顯示的為準；找不到時，在 Finder 的 `~/Library/Application Support/` 裡找名稱含 `metaquotes` 的資料夾。
3. 開啟 MetaEditor 並編譯，**用選單或按鈕即可，不需要 F 鍵**（很多 Mac 鍵盤沒有直接可用的 F4／F7）：
   - MT 上方工具列的 MetaEditor 圖示，或選單「工具 → MetaQuotes Language Editor」。
   - 在 MetaEditor 左側導航的 Experts 裡雙擊 `OneBullExSync`。
   - 按工具列的編譯按鈕（MT4 繁中介面顯示為「**編寫**」）。
   - 下方應顯示 `0 errors, 0 warnings`。編譯成功只代表程式可以執行，同步是否成功要到步驟 6 才確認。
4. 回到 MT，「導航」視窗的「EA交易」按右鍵重新整理，就會看到 `OneBullExSync`。

## 3. 允許連線到接收程式（WebRequest）

從 MT **上方選單**進入：MT4 是「**工具 → 選項 → EA交易**」，MT5 是「**工具 → 設定 → EA交易**」（依版本也可能叫「專家顧問」或 Tools → Options → Expert Advisors，以畫面為準）。

- 勾選 **允許 WebRequest 的網址**（Allow WebRequest for listed URL）
- 新增一行：接收程式的網址，**只填到網域**，例如 `https://203-0-113-10.sslip.io`（不要加 `/webhook`）

沒有這一步，同步程式會顯示 `WebRequest error 4060`（MT4）或 `4014`（MT5）。

> 三個容易搞混的地方：
> - **工具 → 選項／設定 → EA交易**：終端機層級的設定，WebRequest 網址在這裡。
> - **導航 → EA交易 → OneBullExSync**：找到 EA 程式、拖到圖表的地方。
> - **圖表上 EA 的屬性視窗 → 輸入參數（MT4）／輸入（MT5）**：填 WebhookURL、倍數等參數的地方。
>
> WebRequest 填的是**根網址**（不含 `/webhook`）；EA 參數的 WebhookURL 才是完整的 `/webhook` 網址。
>
> 工具列上的「演算法交易」按鈕不是上面任何一個設定頁。

## 4. 查規格、算倍數

掛 EA 之前先算好 `Multiplier`。**先確認 MT 已經登入並連線**（上方「登入並確認連線」）再查規格：未連線時，規格視窗可能顯示舊的快取值（實測曾在未連線時看到黃金每手 250，連線後重查才是 100），不能拿來計算。兩端都要查：

| 要查的 | 在哪裡查 |
| --- | --- |
| MT 每手合約數量、最小交易量、交易步長 | MT「市場報價」在商品上按右鍵 →「規格」。下單視窗預設的 `1.00` 不是最小手數，下拉選項也只是輔助，以規格視窗為準 |
| OneBullEx 每張面值、最小張數、1 張名目金額 | 接收程式主機：`sudo bash ~/onebullex-tradingview-mt4-mt5-bridge/bridge/install.sh spec XAUSPARTANS_USDT`。主機是較早版本、沒有 `spec` 指令時，用 `sudo python3 ~/onebullex-tradingview-mt4-mt5-bridge/bridge/obx_tool.py spec XAUSPARTANS_USDT`；不需要為了新指令去升級正在 LIVE 的主機 |

```
OneBullEx 張數 = MT 手數 × MT 每手合約數量 × Multiplier ÷ OneBullEx 每張面值
```

例：MT 黃金每手 100 盎司、OneBullEx 每張 0.001 盎司（實測時 MetaQuotes-Demo 的 XAUUSD 與 XM MT4 的 GOLD 都是每手 100；其他券商請自己查）。

| Multiplier | MT 0.01 手 | MT 0.02 手 | MT 1 手 |
| --- | --- | --- | --- |
| 1（兩邊一樣大） | 1,000 張 | 2,000 張 | 100,000 張 |
| 0.001 | 1 張 | 2 張 | 100 張 |

- `Multiplier = 1` 代表 OneBullEx 的部位和 MT 一樣大。再依你在斯巴達帳戶想承擔的部位大小調整；兩邊資金比例可以參考，但要用上面的公式確認實際張數與名目金額（[06](06-quantity-and-risk.md)）。
- **最低名目金額**：交易所可能拒絕名目金額太小的單（例如回覆 `notional can not less than 5 USDT`）。黃金 1 張約 4 USDT 會被拒，2 張約 8 USDT 才會成交。最小測試數量要同時滿足：最小張數、整數張、最低名目金額。
- 換算不足 1 張會捨去成 0（不下單）。
- 建議設定持倉上限防止倍數填錯：`sudo bash install.sh set TV_MAX_QTY <張數>`。

## 5. 掛上同步程式

1. 「市場報價」找到商品（例如 XAUUSD 或 GOLD；看不到就在視窗按右鍵 →「全部顯示」）→ 右鍵 →「開啟圖表」（MT4 是「圖表視窗」）。
2. 從「導航 → EA交易」把 `OneBullExSync` 拖到這張圖表的 K 線區。（只要掛一次，`SymbolMap` 裡的所有商品都會同步。）
3. 跳出的視窗上方點「**輸入參數**」（MT4）或「**輸入**」（MT5）分頁，逐列填寫。畫面上可能顯示的是英文說明，括號內是對應的參數。**預設值是 `SymbolMap=XAUUSD=…`、`Multiplier=1.0`，一定要改，不能直接按確定**：

| 參數 | 填什麼 |
| --- | --- |
| Webhook URL（`WebhookURL`） | 安裝時顯示的完整網址，例如 `https://203-0-113-10.sslip.io/webhook` |
| Passphrase（`Passphrase`） | 安裝時顯示的 passphrase（見下方「Passphrase」） |
| MT symbol=OneBullEx symbol（`SymbolMap`） | `MT商品=OneBullEx交易對`，多個用逗號分隔。MT 名稱要和市場報價**完全一樣**，例如 `XAUUSD=XAUSPARTANS_USDT`、`GOLD=XAUSPARTANS_USDT`、`XAUUSD.m=XAUSPARTANS_USDT` |
| OneBullEx size = MT size x Multiplier（`Multiplier`） | 步驟 4 算出的倍數 |
| false: send net position…（`HedgeMode`） | `false` = 只同步淨部位；`true` = 多單、空單分開同步，見下方「鎖倉」 |
| -1 = all…（`MagicFilter`） | `-1` = 同步所有持倉；`0` = **只同步手動單**；其他數字 = 只同步該 magic number 的 EA 單（向策略 EA 確認 magic number） |
| How often…（`PollSeconds`） | 幾秒檢查一次，預設 1 |
| Resend…（`ResendSeconds`） | 持倉沒變時多久重送一次，預設 60；0 = 只在變化時送 |
| Only sync this account…（`LockAccount`） | 只同步這個 MT 帳號；0 = 掛上時登入的帳號 |

4. 按「確定」。圖表左上角會顯示每個商品的多、空數量，以及最後一次送出的時間或錯誤。

**掛上時會立刻同步目前的持倉。** MT 有持倉，OneBullEx 會馬上開出對應倉位；MT 空倉，OneBullEx 這個交易對會被對齊成 0（原本有倉位會被平掉）。掛上前先確認兩端的狀態。

## 6. 先試跑，再小量 LIVE

```bash
sudo bash ~/onebullex-tradingview-mt4-mt5-bridge/bridge/install.sh dryrun
sudo bash ~/onebullex-tradingview-mt4-mt5-bridge/bridge/install.sh recent
```

在 MT 開一筆會換算成至少 2 張的單（例如 Multiplier 0.001 時開 0.02 手黃金），`recent` 應出現：

```
收到訊號 XAUSPARTANS_USDT target=2.00000000 ×0.00100000 unit=coin
[試跑，不下單] XAUSPARTANS_USDT 目前 0 張 → 目標 2 張：開多 2 張
```

`target=` 後面是換算前的數量（MT 手數 × 每手合約數量），`×` 後面是倍數，`目標 N 張` 才是 OneBullEx 的張數。

確認張數合理、取得同意後（先說明會在哪個 OneBullEx 帳戶真實下單、最多幾張、約多少 USDT；由使用者自己在 MT 下單）：

1. 先在 MT 平倉，確認兩端都是空倉、沒有掛單，而且**只有這一個 MT 在同步這個交易對**（例如測 MT4 前，先移除 MT5 的同步程式）。
2. 確認 OneBullEx 上這個交易對的槓桿（畫面上的倍數）。和接收程式不同時，空倉時執行 `sudo bash install.sh set TV_LEVERAGE <倍數>`，避免 `leverage not match`。MT 模擬帳戶的槓桿不需要和 OneBullEx 一樣。
3. `sudo bash install.sh live`。
4. 依序測試，每一步看紀錄確認 `成交` 與 `完成，淨部位 N 張`，並等一次 60 秒重送確認 `已等於目標，不下單`：

| 步驟 | MT 操作（例：Multiplier 0.001、黃金每手 100） | OneBullEx 預期 |
| --- | --- | --- |
| 1 | 空倉掛上 EA | 目標 0，不下單 |
| 2 | 買入 0.02 手 | 開多 2 張，淨部位 +2 |
| 3 | 對這筆多單「平倉」 | 平多 2 張，淨部位 0 |
| 4 | 賣出 0.04 手 | 開空 4 張，淨部位 −4 |
| 5 | 對這筆空單部分平倉 0.02 手 | 平空 2 張，淨部位 −2 |
| 6 | 剩下的 0.02 手平倉 | 平空 2 張，淨部位 0 |

- **部分平倉的做法**：在 MT 下方「交易」分頁對原持倉開啟交易單（雙擊或右鍵），把平倉量改成 0.02，按該訂單的「平倉」。不要另開一筆反向單（鎖倉帳戶會變成另一筆持倉），也不要在 OneBullEx 手動平倉。
- 每一步的變動都用 2 張以上（黃金 1 張約 4 USDT，低於最低名目金額 5 USDT 會被拒）。平倉單是否也受最低名目金額限制尚未驗證，保守起見每次變動都維持 2 張以上。被拒單時不要自行放大數量，說明原因並取得同意後再調整。
- 以紀錄裡的成交與淨部位為準；未核對含手續費的淨損益前，不要用兩個成交價推算盈虧。

測試完要不要切回試跑由你決定：切回試跑只是暫停真實下單，不代表設定沒完成；保持 LIVE 時，之後在 MT 下的任何單都會在 OneBullEx 真實下單。

## Passphrase

- **安裝時就存起來**：`install.sh install` 第一次會顯示 passphrase，請馬上存進密碼管理器，並註明是哪一台主機、哪個機器人帳戶的。
- **沿用**：同一套接收程式、沒有更換過的話，MT4、MT5、TradingView 都用同一串。
- **它不是**券商密碼，也不是 OneBullEx 的 API Secret。
- **忘記了**：不用重設。在接收程式主機上自己的 SSH 終端機執行下面這行查看（不要貼給別人或 AI）：

  ```bash
  sudo grep '^TV_PASSPHRASE=' /etc/onebullex-tv.env
  ```

- **`install.sh passphrase` 會產生一組新的**，舊的立刻失效，所有 TradingView 警報和 MT 同步程式都要一起更新。只有外流時才需要換。

## 鎖倉（同時持有多空）

| HedgeMode | MT 多 1 手、空 1 手時 | 適合 |
| --- | --- | --- |
| `false`（淨部位） | OneBullEx 空手（淨部位 0） | 一般情況。盈虧和鎖倉相同，佔用保證金與手續費較少 |
| `true`（多空分開） | OneBullEx 也同時持有多、空各一份 | 希望 OneBullEx 帳面和 MT 完全一致，例如讓跟單者看到同樣的鎖倉 |

`HedgeMode = true` 需要斯巴達帳戶可以同時持有多空（合倉的雙向持倉）。兩邊都會佔用保證金，成交筆數也比較多。

MT 鎖倉（Hedge）帳戶要結束一筆單時，對那筆持倉按「平倉」；另開一筆反向單會變成另一筆持倉，不是平倉。

## 停止同步

- 移除同步程式**不會**平掉 OneBullEx 的持倉，只是之後不再同步。
- 要結束並平倉：先在 MT 平倉 → 確認 OneBullEx 也歸零（紀錄出現 `完成，淨部位 0 張`）→ 再移除同步程式或切換模式。
- 同步程式移除期間，在 MT 開平倉不會反映到 OneBullEx。重新掛上時，會一次對齊到 MT 當下的持倉。

## 注意

- **同一個交易對只用一個來源。** 同一個 OneBullEx 帳戶的同一個交易對，不要同時用 TradingView 警報、另一台 MT 或手動下單，持倉會互相覆蓋。也不要在 OneBullEx 手動平倉：重送時會被開回來。
- **價格與時間差。** OneBullEx 用自己的市價成交，跟 MT 的成交價會有差距，再加上約 1–2 秒延遲。剝頭皮等極短線策略，差距會比較明顯。
- **休市時間不同。** MT 的黃金週末休市。如果 OneBullEx 在 MT 休市期間仍有報價，持倉會照常受價格影響，而 MT 上無法調整。
- **MT 斷線。** MT 與券商斷線時，同步程式會暫停並在圖表顯示原因，恢復後自動對齊。
- **權益在哪裡看。** MT 下方「交易」分頁的「淨值」（或「權益」，依版本名稱不同）。

## 疑難排解

| 圖表左上角或紀錄顯示 | 原因與處理 |
| --- | --- |
| `WebRequest error 4060`／`4014` | 步驟 3 沒有加入網址、網址填錯（只填到網域），或勾選後沒按確定 |
| `WebRequest error 5203`、`5200` 等 | 連不到主機。檢查網址、主機防火牆 443、接收程式是否在跑（`install.sh status`） |
| `HTTP 403 {"ok":false,"error":"forbidden"}` | 來源 IP 不在允許清單。`install.sh recent` 找被拒的 IP（家用網路 IP 可能變了），加進 `TV_ALLOWED_IPS` |
| `HTTP 401` | Passphrase 填錯 |
| `HTTP 400 ...` | 交易對名稱錯誤或不在 `TV_SYMBOLS` 清單 |
| `symbol not found` | `SymbolMap` 的 MT 商品名稱和市場報價不一致（注意 `.m`、`.pro` 等後綴，或券商用 `GOLD` 而不是 `XAUUSD`） |
| 右下角「帳戶無效」、「新交易單」是灰色、圖表停在舊日期 | MT 沒有真的登入。確認選對券商伺服器、用的是 MT 交易密碼（不是會員網站密碼），用「文件／檔案 → 登入交易帳戶」重新登入 |
| 規格數字和預期差很多（例如黃金每手 250） | 可能是未連線時的舊快取。先確認登入成功，再重新打開規格視窗 |
| `not connected to broker` | MT 與券商斷線，恢復後會自動同步 |
| `is not the locked account` | 目前登入的帳號不是掛上時的帳號；重新掛上，或設定 `LockAccount` |
| 顯示 `sent` 但 OneBullEx 沒動 | `sent` 只代表接收程式收下了訊號。看 `install.sh recent`：試跑模式、換算不足 1 張、超過持倉上限、被交易所拒單等 |
| 紀錄 `notional can not less than 5 USDT` | 名目金額低於交易所下限。調大 MT 手數或 Multiplier（取得同意後），讓張數 × 面值 × 價格高於下限 |
| 紀錄 `leverage not match` | 接收程式送出的槓桿和 OneBullEx 上該交易對的槓桿不同（空倉時也可能發生）。空倉時 `install.sh set TV_LEVERAGE <OneBullEx 畫面上的倍數>` |
| `install.sh logs` 停不下來 | 先點一下終端機視窗，按 Control+C（不是 Command+C）。只想看最近的紀錄用 `install.sh recent`；較早版本沒有 `recent` 時用 `sudo journalctl -u onebullex-tv -n 60 --no-pager` |
| `obx_tool.py` 顯示讀不到設定檔 | 用 `sudo bash install.sh spec <交易對>`／`install.sh balance`，不要放寬設定檔權限 |
